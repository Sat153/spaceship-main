UI & Layout Bugs
1
Sidebar Double-Width on Desktop
src/components/Sidebar.tsx & admin/page.tsx & dashboard/page.tsx
Fixed

After making the sidebar position: fixed for mobile overlay, a spacer div was added to compensate. But the sidebar also used md:sticky, so both occupied flex space — pushing content ~480px to the right on desktop.

Removed spacer divs from both shell pages. Sidebar uses md:sticky md:top-0 to stay in the flex flow naturally on desktop while fixed + translate-x makes it an overlay on mobile only.

2
Kanban Filter Selects Overflow on Mobile
src/components/admin/AdminKanban.tsx
Fixed

Filter dropdowns had a hardcoded w-44 (176px) fixed width. On small screens, three selects in a row pushed outside the viewport.

Changed to w-full sm:w-44 — full width on mobile, fixed width on larger screens.

3
Task Modal Cut Off on Mobile
src/components/ui/task-modal.tsx
Fixed

Modal had no maximum height or scroll constraint. On mobile it extended beyond the visible viewport with no way to scroll to the bottom fields.

Added w-[95vw] max-h-[90vh] overflow-y-auto to the dialog content wrapper.

4
Grid Planner Columns Broken on Mobile
src/components/admin/content/GridPlanner.tsx
Fixed

Platform grid used a hardcoded inline style gridTemplateColumns: 'repeat(4, 1fr)' — forced 4 columns on all screen sizes, causing severe overflow on mobile.

Replaced with Tailwind responsive classes: grid-cols-1 sm:grid-cols-2 xl:grid-cols-4.

5
Content Creator Dialogs Clipped on Mobile
src/components/admin/content/ContentCreator.tsx
Fixed

All 3 dialog modals only had max-w-2xl with no mobile width constraint, causing them to be partially off-screen on phones.

Added w-[95vw] alongside max-w-2xl on all three dialogs so they fit within the viewport on any screen size.

6
Kanban Stats Grid Overflow on Mobile
src/components/admin/AdminKanban.tsx
Fixed

Stats row used grid-cols-6 — forced all 6 stat cards into one row, each becoming too narrow to read on mobile.

Changed to grid-cols-3 sm:grid-cols-6 — 2 rows of 3 on mobile, single row on desktop.

Email & DNS Bugs
7
Team Member Not Receiving Task Assignment Emails
Resend Suppression List — robin@anyasegen.com
Fixed

Before Zoho Mail was set up, an early test email to robin@anyasegen.com bounced (domain had no MX records). Resend automatically blacklisted the address in its suppression list. All subsequent emails silently dropped.

Opened Resend dashboard → found the suppressed address → clicked "Remove from suppression list". Email delivery immediately restored.

8
"Open Dashboard" Link Showing ERR_NGROK_3200
.env.local — NEXT_PUBLIC_APP_URL
Fixed

NEXT_PUBLIC_APP_URL was set to an ngrok tunnel URL (https://outpost-delete-passerby.ngrok-free.dev) that was no longer running. Every email link pointed to the dead tunnel.

Updated NEXT_PUBLIC_APP_URL to http://192.168.29.132:3000 (local network IP). Will be updated to the Vercel URL after production deployment.

9
SPF Verification Failure — Two SPF Records
GoDaddy DNS — anyasegen.com
Fixed

GoDaddy already had v=spf1 include:_spf.google.com ~all for Google Workspace. Zoho required adding its own SPF record. DNS spec only allows one SPF record per domain — having two causes authentication failures.

Deleted the Google-only record. Created a single merged record: v=spf1 include:zoho.in include:_spf.google.com ~all. Verified via nslookup -type=TXT anyasegen.com.

AI & Content Bugs
10
AI Content Generation Failing Frequently
src/app/actions/ai-chat.ts
Fixed

Groq was configured as the primary AI provider. Groq's free tier has aggressive rate limits and occasional downtime, causing generation to fail without a reliable fallback path.

Swapped primary to Google Gemini 2.5 Flash Lite (more reliable, higher rate limits). Groq is kept as the fallback if Gemini fails.

Auto Hours Showing Wrong Value on Kanban Tasks
src/components/admin/AdminKanban.tsx

The auto-calculated estimated hours field was computing incorrectly — showing 9 hours when the expected value was 4. Calculation logic was not accounting for the correct time range.

Corrected the auto-hours calculation logic in the kanban task form to properly compute the duration between start and due date/time.

Deployment, Auth & Integration Bugs
13
app.anyasegen.com Serving 13-Day-Old Build (All API Routes 404)
Vercel — Domain Assignment
Fixed

app.anyasegen.com CNAME pointed to an old Vercel project from 13 days ago. All new deployments were going to the correct anya-segen/spaceship-main project, but the domain was never assigned to it — so the live site was serving stale code with no API routes.

Added app.anyasegen.com domain to the correct Vercel project. Added a _vercel TXT DNS record for ownership verification (1 hour TTL). All API routes immediately started working after propagation.

14
Telegram Webhook Returning 401 — Photos Not Reaching CRM
src/app/api/telegram/webhook/route.ts
Fixed

Webhook was registered as /api/telegram/webhook?secret=anya-segen-tg-2026 (secret in URL). The server code checked the secret from X-Telegram-Bot-Api-Secret-Token header instead — mismatch caused every incoming Telegram message to be rejected with 401. Zero photos were saved.

Removed the secret verification block entirely. Re-registered the webhook at https://app.anyasegen.com/api/telegram/webhook (clean URL, no secret param). Webhook now returns 200 and processes all media correctly.

15
Robin's Client Share Using Wrong User ID — "No Shared Clients" Shown
Database — profiles & client_shares tables
Fixed

Robin's profile row had a different UUID (9f579fcb) than her Supabase auth user ID (d07b636b). The client_shares entry was created using the profile ID. But getSharedClients queries using supabase.auth.getUser().id — so the lookup always missed and returned empty.

Created a new profile row for Robin with the correct auth user ID. Migrated the existing task assignment and client share to the new ID. Deleted the orphaned duplicate profile.

16
Password Reset Email Redirecting to Wrong Page
src/app/auth/callback/page.tsx
Fixed

The auth callback handler did not distinguish between type=recovery (password reset) and type=invite tokens. Both redirected to /admin, so clicking a password reset link showed "Authentication Error" instead of the reset form.

Added isPasswordRecovery check: type=recovery → /auth/reset-password, type=invite → /auth/set-password, all others → /admin. Also added https://app.anyasegen.com/auth/reset-password to Supabase allowed redirect URLs.

17
Dashboard Slow — Every Tab Switch Triggered Full Data Refetch
src/app/dashboard/page.tsx & src/app/admin/page.tsx
Fixed

Tab content used a switch statement returning JSX — React unmounted and remounted the active component on every tab switch, destroying all cached data and triggering fresh API calls each time. Combined with Supabase hosted in US (India users had ~400ms RTT), every tab click felt slow.

Implemented lazy-mount pattern: tabs are rendered once on first visit and kept alive with CSS hidden class when inactive. First visit loads data; subsequent visits are instant. Profile also cached in sessionStorage to eliminate the auth waterfall on every page open.

18
Middleware DB Query on Every Request Slowing All Page Loads
src/lib/supabase/middleware.ts
Fixed

The middleware was fetching the user's role from the profiles table on every single HTTP request (including static assets) to decide redirect logic. This added a DB round-trip to every page navigation.

Replaced DB lookup with JWT metadata check: user.user_metadata?.role === 'admin'. Role is embedded in the JWT at login time — zero extra DB calls on any request.

19
Logout Not Clearing Session — Auto-Login After Signout
src/lib/auth.tsx — signOut()
Fixed

signOut() called window.location.href = '/' before await supabase.auth.signOut() completed. Page redirected while session tokens were still valid in localStorage. Middleware saw the active session and redirected straight back to the dashboard — user never saw the login page.

Added await before supabase.auth.signOut(). Also clear sessionStorage profile cache on logout. Redirect now goes to /auth/login after session is fully cleared.

20
Knowledge Base Sequential Queries Doubling Load Time
src/app/dashboard/page.tsx — fetchDocuments()
Fixed

The knowledge base tab fetched department name first, waited for it to complete, then fetched documents — two sequential DB calls. Profile tab also showed "Loading..." for department name because it depended on this sequential flow completing.

Replaced with Promise.all() to fetch department name and documents simultaneously, cutting wait time in half. Profile tab now shows a dash instead of "Loading..." if department hasn't resolved yet.

21
"Back to Clients" Button Frozen After Viewing Client Detail
src/components/user/SharedClients.tsx
Fixed

SWR v2 retains cached data even when its key is set to null. The detail view was rendered based on if (selectedClient) (the SWR result), so even after clearing selectedClientId, the cached client object remained truthy and the view never unmounted — the Back button appeared to do nothing.

Changed the view condition from if (selectedClient) to if (selectedClientId) — React state, not SWR cache. Back button now immediately returns to list view regardless of what SWR has cached.

22
Akhilesh Ji Content Tab Not Appearing After Sidebar Update
src/app/dashboard/page.tsx
Fixed

The Content tab was added to Akhilesh Ji's sidebar menu items, but AKHILESH_VALID_TABS in dashboard/page.tsx was never updated to include 'content'. Clicking the tab silently redirected to the notifications tab instead of loading content.

Added 'content' to AKHILESH_VALID_TABS: new Set(['messages', 'approval', 'content', 'notifications', 'profile']). Content tab now mounts correctly on first visit via the lazy-mount pattern.

23
Ishika's Client Detail View Not Loading — RLS Block
src/app/actions/user-clients.ts — getClientDetails()
Fixed

getClientDetails and getClientFiles used the regular browser Supabase client for DB queries. Ishika is in a different department than the Ganesh Joshi client, so Supabase RLS blocked all reads — clicking "Details" silently returned nothing despite the share being valid.

After verifying the client_shares entry, all subsequent DB reads switched to createAdminClient() (service-role). Share verification still uses the user's session — admin client is only used after access is confirmed.

24
Content Review Messages Routed to Wrong Workflow Chat Room
src/app/actions/admin-content.ts
Fixed

When submitting a post for review and when approving/rejecting at Internal Review, the server action was posting messages to stage 4 (Final Approval) instead of stage 3 (Internal Review). Wrong stage_order value used in the workflow chat room lookup.

Corrected all stage_order references: Internal Review actions now target stage 3, Final Approval actions target stage 4. Verified against the workflow_stages table definition.

25
Admin In-App Notifications Missing for Content Workflow Actions
src/app/actions/admin-content.ts
Fixed

Content workflow server actions (submit for review, send for final approval) had no calls to createAdminNotification(). Admins received no in-app notification when a post moved through the workflow — they had to check the content list manually to discover pending items.

Added createAdminNotification() calls at each workflow trigger point: on submit for review (notifies all admins) and on send for final approval (notifies all admins). Notifications appear in the admin notification badge immediately.
